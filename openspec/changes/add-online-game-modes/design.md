# Design: Online Game Modes and Kick

## Context
- 服务端 `online.Server` 只有一个 `run` goroutine 处理所有事件和计时器，玩法规则目前直接写在 server.go 里（Word Drop）
- 客户端 `online.Battle` 由服务端消息驱动，UI 每次 tick 渲染它的状态
- 用户已确认：
  - 最长时间指整局时间上限，与个数先到者结束
  - 整句按字母数计分，回车时输错不清空
  - 单词池盘面满了替换最早出现的未占有单词
  - 被踢的玩家可以重新加入

## Goals / Non-Goals
- Goals：三种玩法共用房间、大厅、结算流程；判定始终由服务端完成
- Non-Goals：观战、断线重连、自定义词库、队伍模式

## Decisions

### 1. 玩法用接口拆分
```go
type gameMode interface {
    start(now time.Time)                     // 开局，返回首批消息
    onTimer(now time.Time)                   // 计时器到期
    onSubmit(p *serverPlayer, msg Message)   // 玩家提交
    finished() bool
}
```
`run` 只负责公共流程：3 秒倒计时、整局时间上限、断线提前结束、结算。三种玩法分别放在 `mode_word_drop.go`、`mode_sentence_race.go`、`mode_word_pool.go`。每个玩法只用一个计时器，由 `run` 统一调度，所以仍然只有一个 goroutine 修改状态。

### 2. 设置的数据结构
```go
type Settings struct {
    Count       int  // Word Drop / Sentence Race：个数
    TimeLimit   int  // 秒；Word Drop / Sentence Race 为上限，Word Pool 为时长
    SpawnRate   int  // Word Pool：每秒出词个数
    AllowSteal  bool // Word Pool：是否允许掠夺
}
```
每个玩法声明自己用到的设置项、可选值和默认值（`settings.go`）：
| 玩法 | 设置项 | 可选值 | 默认 |
|---|---|---|---|
| Word Drop | Count | 5, 10, 15, 20, 30 | 10 |
| Word Drop | TimeLimit | 60, 90, 120, 180, 300 | 120 |
| Sentence Race | Count | 3, 5, 8, 10 | 5 |
| Sentence Race | TimeLimit | 60, 120, 180, 300 | 180 |
| Word Pool | TimeLimit | 30, 60, 90, 120 | 60 |
| Word Pool | SpawnRate | 1, 2, 3 | 1 |
| Word Pool | AllowSteal | Off, On | Off |

- 使用固定的档位而不是任意数字，左右键切换，不需要文本输入
- 服务端只接受档位里的值，其他值一律忽略
- 切换玩法时，设置重置为新玩法的默认值

### 3. 大厅菜单
用户要求：上下选择选项，回车进入调整，不要打字输入。大厅上半部分是一个竖排菜单：
```
  > Mode          Word Drop
    Words         10
    Time limit    120s
    Start Game
```
- 上下键移动选中项；在玩法或设置项上按回车，进入该项的滚轮页面
- 回车已用于进入调整，所以开局放在菜单最后一项 Start Game，选中后按回车开始
- 只有房主能操作菜单；非房主看到同样的菜单和当前值，但没有选中标记
- Tab 改名、K 踢人、Esc 关闭房间或离开，与选中项无关

### 3.1 大厅布局：左设置、右玩家
内容区分为左右两半（各 38 列）：
```
  Room  │  192.168.1.20:7788  │  Players 3/4
                                    ╭──────────────────────────────╮
                                    │ Alice host you               │
    Mode          Word Drop         ╰──────────────────────────────╯
  > Words         10                ╭──────────────────────────────╮
    Time limit    120s              │ Bob                          │
    Start Game                      ╰──────────────────────────────╯
```
- 左半部分是设置菜单；菜单上方留两行空白，给滚轮的上方档位留位置
- 右半部分每行一名玩家，每人一个圆角边框卡片（3 行高），4 名玩家正好占满内容区，所以人数移到顶部标题里
- 本人的卡片边框使用自己的颜色，其他人为灰色

### 3.2 就地调整：滚轮在取值处
用户要求调整时看起来像在原视图操作。按回车后不切换页面，只改变左半部分：
```
                      1             ← 较淡（颜色 244）
  > Words/sec       ▶ 2 ◀           ← 名称与原位置完全重合；当前值与原取值同列
                      3             ← 较淡（颜色 244）
```
- 其他设置项隐藏，但保留空行，所以选中项的行号和列号都不变
- 当前值所在列与原取值列相同：原来名称和取值之间的两格空白正好放下 “▶ ”
- 上下各显示两个相邻档位（离得越远颜色越淡），与当前值左对齐；越过菜单上下边界的档位不显示
- 右半部分的玩家卡片照常显示
- 上键滚到上方的档位，下键滚到下方的档位，到头不循环；靠近两端时空出的位置留白
- 档位按从小到大排列（玩法和开关按定义顺序）
- 回车确认：发送 set_option，回到大厅菜单；Esc 取消：丢弃本次滚动，回到大厅菜单
- 滚动过程只在本地预览，确认后才广播，其他玩家不会看到中间状态
- 房主正在调整时，房主自己开始游戏之前必须先确认或取消，所以不会出现调整到一半开局的情况；但如果房主调整时有玩家断开，大厅列表照常刷新

### 3.3 踢人选择框
上下键和回车已经用于菜单，所以踢人放在单独的选择框里：
- 房主按 K 打开选择框，只是把右半部分的玩家卡片变成可选状态：选中的卡片边框变红并显示 ✕，房主自己的卡片变灰；只有自己一人时提示 “No one to kick”
- 选择框内上下键选择玩家，回车踢出，Esc 取消
- 选择框打开时，其他按键全部无效，避免误操作

### 4. 踢人
- `kick{player_id}`：只有房主能发起，不能踢自己，只在大厅阶段有效
- 服务端先给被踢者发送 `kicked`，再关闭他的连接，然后广播 `lobby`
- 被踢者看到 `kicked` 后回到联机菜单，显示 “You were kicked”，并重新开始浏览房间；之后可以照常从列表加入
- 被踢者的连接关闭时，读 goroutine 还会再报告一次断开。此时这名玩家已经被移出列表，所以 `playerByConn` 找不到他，这个事件会被直接忽略

### 5. Sentence Race
- 句子来源：`data/sentences.txt`，由 `game.DrawSentences(n)` 抽取，不重复
- 服务端广播 `sentence{index, text}`；玩家按回车时，只有输入与句子完全一致才发送 `claim{index, word: text}`
- 计分：句中的字母数（`unicode.IsLetter`），空格和标点不计分
- 客户端输入：接受所有可打印的 ASCII 字符，包括空格和标点；Backspace 删除；回车时输入不对就保持原样，同时提示 “Not yet - fix the red part”
- 一句被拿走后广播 `word_claimed`，1 秒后出下一句；不会作废（整局时间上限到了就结束）
- 计时器：句子之间的 1 秒间隔，以及整局时间上限

### 6. Word Pool
- 盘面：36 格（6 行 × 6 列），每格可能为空，或者放一个单词，单词带有占有者 ID（0 表示空闲）
- 出词：每隔 `1s / SpawnRate` 出一个新词，词语互不重复，位置是随机的空格；没有空格时替换出现最早的空闲单词；如果没有空格也没有空闲单词，就跳过本次
- 广播 `pool_spawn{slot, word}`
- 占有：`claim{slot, word}` 有效的条件：
  - 这一格的单词就是 `word`
  - 单词空闲；或者开启了掠夺，并且占有者不是提交者本人
- 有效时广播 `pool_claimed{slot, player_id, from}`，`from` 为原占有者，0 表示原来空闲
- 客户端输入：只接受字母，与 Word Drop 一致；回车时在盘面上查找与输入一致、且当前规则允许占有的单词，找到就发送 claim，找不到就清空输入
- 结算：每人的分数等于手中单词的字母数之和，单词数等于手中单词的个数
- 计时器：出词间隔，以及游戏时长

### 7. 颜色
每个玩家按加入顺序分配一种颜色：红、蓝、绿、黄。比分栏、单词池盘面、结算界面都用同一种颜色标识同一名玩家。玩家 ID 和颜色是一一对应的（`playerColor(id)`），被踢的玩家重新加入时会得到新的 ID 和颜色。

### 8. 协议版本
协议版本升到 3：`lobby` 新增 settings 字段，并且新增了多种消息类型。旧版客户端的发现包和加入都会因为版本不同被拒绝。

### 9. 实时输入同步
- 新增 `typing{word}`：客户端每次 tick（33ms）检查一次输入，变化了才发送，所以无论打字多快，每人每秒最多约 30 条
- 服务端只在对局中转发给其他玩家，附上 player_id；转发前去掉控制字符并截断到 200 字符，防止通过别人的终端注入转义序列
- 客户端在单词或句子切换时清空所有人的输入，不需要服务端另发重置消息
- 界面：每人一行，本人固定在最下面；输入与题目逐字对齐，打错的字符单独标红，其他人打对的字符为灰色（单词池用各自颜色），本人为绿色
- 单词掉落：掉落区缩为 5 行，下方再印一次单词作为对齐基准
- 整句：每个折行后面紧跟每人对应这一行的输入。所有句子在 65 列宽时最多折成 2 行，2 ×（1 行句子 + 4 行玩家）+ 1 行分数 = 11 行，放得进 12 行的内容区。名字列宽 6，长名字截为 “前 3 + * + 后 2”
- 单词池：没有唯一题目，每行用盘面上与输入开头相同部分最长的单词作为目标
- 玩家颜色改为蓝、黄、紫、青，因为绿色和红色已用于对错标记

## Risks / Trade-offs
- 单词池最多 3 词/秒、每词一条消息，加上 4 名玩家的 claim，流量很小，没有性能问题
- 实时输入每人每秒最多约 30 条、每条几十字节，4 人房间在局域网中完全可以承受
- 句子较长时，80 列宽的界面放不下 → 按单词自动换行，最长的句子是 121 个字符，最多占 2 行
- 掠夺开启时，同一个单词可能被来回抢 → 这是预期的玩法，由服务端按消息到达顺序裁决，不会出现不一致
