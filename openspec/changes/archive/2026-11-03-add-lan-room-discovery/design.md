# Design: LAN Room Discovery

## Context
- 已有的联机实现：房主进程运行 `online.Server`，在 TCP `online_port` 上监听；加入方用 `online.Connect` 连接，并发送带房间号的 `join` 消息
- 目标环境是同一局域网（同一网段）内的 2–4 名玩家
- 用户已确认：不需要房间号；不需要手动输入 IP，只保留局域网房间列表；对局中的房间显示为不可加入；可以接受防火墙弹窗

## Goals / Non-Goals
- Goals：
  - 进入联机菜单后，1 秒左右就能看到局域网内的房间，选中后直接加入
  - 同一台电脑上开多个客户端浏览房间时互不影响，方便本机测试
- Non-Goals：
  - 跨网段、跨 VPN 联机（用户明确只要局域网列表，不保留手动输入 IP）
  - 扫描端口
  - 私密房间、密码

## Decisions

### 1. 查询-回复，而不是房主主动广播
玩家每秒从一个临时 UDP 端口广播一次 `discover` 查询；房主在 UDP `online_port` 上监听，收到后向查询来源单播回复 `room_info`。
- 只有房主需要占用固定的 UDP 端口，它本来就要占用同号的 TCP 端口，所以每台机器同一时间只能有一个房主，这一点不变
- 浏览房间的客户端使用系统分配的端口，同一台机器开多少个都不会冲突
- 备选方案：房主每秒广播、浏览方监听固定端口。这样多个浏览方需要共享同一个端口，要设置 SO_REUSEADDR，而且各平台的行为不一致，所以不采用

### 2. 查询的发送目标
每次查询发往三个地址：
- `255.255.255.255:online_port`（受限广播）
- 每个已启用的 IPv4 网卡的定向广播地址（例如 `192.168.1.255`）。Windows 在多网卡时只会从一块网卡发出受限广播，所以需要逐个网卡补发
- `127.0.0.1:online_port`，确保本机的房间一定能被发现

### 3. 消息格式
沿用 JSON，每个 UDP 包一条消息，复用 `Message` 结构体：
| type | 方向 | 字段 |
|---|---|---|
| `discover` | 玩家 → 广播 | version |
| `room_info` | 房主 → 玩家（单播） | version, room_id, name（房主昵称）, port（TCP 端口）, players, max_players, in_game |

- 房主的 IP 取自 UDP 包的来源地址，不放在消息里
- `room_id` 是房主启动时生成的随机串，用于去重：同一个房间可能经由多块网卡或回环地址收到多份回复。去重时优先保留非回环地址
- `version` 与当前协议版本不一致的消息直接丢弃，所以不同版本的房间不会出现在列表里
- 收到的包超过 1 KB，或者不是合法 JSON，也一律丢弃

### 4. 房间列表的生命周期
- `online.Browser` 只在联机菜单显示时运行：进入菜单时启动，离开菜单（进入房间或回到欢迎界面）时停止
- 每个房间记录最后一次收到回复的时间；超过 3 秒没有更新就移除
- UI 每次 tick 都取一份快照。列表按房主昵称和 room_id 排序，保证顺序稳定
- 当前选中项按 room_id 记录，而不是按下标，这样列表刷新时选中的房间不会跳动；选中的房间消失后，选中项回到 Create Room

### 5. 房主侧的状态快照
房间状态只有 `Server.run` 这一个 goroutine 能修改。每当玩家列表或阶段发生变化，`run` 就把人数、是否在对局中、房主昵称写入一个由互斥锁保护的快照，UDP 回复 goroutine 只读这个快照。房主还没有加入自己的房间时不回复查询。

### 6. 去掉房间号和手动加入，增加协议版本号
- `join` 消息：去掉 `room`，新增 `version`
- 服务端：版本不一致时回复 `join_rejected`（reason=`version_mismatch`），然后断开连接
- 2.0.0 的客户端不发送 `version`（值为 0），所以会被拒绝，并显示它自带的兜底提示 “Join rejected”
- 删除 `Battle.Room`、大厅的房间号显示，以及整个加入表单（界面、状态、按键处理）；大厅改为显示房主的 IP:端口
- `online.Connect(addr, name)` 仍然接受地址参数，地址来自发现到的房间

### 7. 联机菜单的结构
一个可以上下移动的列表：
```
  > Create Room
  ────────────── Rooms on your network ──────────────
    Alice        2/4  Waiting    192.168.1.20
    Bob          4/4  Full       192.168.1.21
    Carol        3/4  In game    192.168.1.35
```
- 没有房间时，在列表区域显示 “Searching for rooms...”
- 对局中或已满的房间用灰色显示，按回车时提示 “Game in progress” 或 “Room is full”，不发起连接
- 连接中显示 “Connecting...”，此时忽略按键；连接失败时在菜单下方显示错误
- 去掉 “Back” 菜单项，统一用 Esc 返回

## Risks / Trade-offs
- 防火墙拦截 UDP，或者网络开启了客户端隔离，导致房间不显示，而且没有手动加入的备用方式 → README 说明需要放行的端口和网络要求；房主大厅仍显示 IP:端口，便于排查
- 列表显示可加入，但点进去时房间刚好满员或开局 → 由服务端判断，客户端照常显示 Room is full / Game in progress
